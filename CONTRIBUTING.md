# Contributing

Contributions should preserve the project's privacy-first, dependency-free design and calm, evidence-based tone.

## Requirements

- Keep the application static and usable from GitHub Pages or a downloaded folder.
- Do not add analytics, telemetry, ads, accounts, remote databases, third-party scripts, CDN assets, or runtime API calls.
- Do not weaken the Content Security Policy.
- Render user-controlled values as text, not HTML.
- Preserve keyboard access, visible focus, mobile layouts, reduced-motion support, and print output.
- Use original writing and link to primary, authoritative sources for factual guidance.
- Distinguish readiness scoring from probability, certification, or guaranteed protection.
- Update `PRIVACY.md`, `SECURITY.md`, and `THREAT-MODEL.md` when behavior changes.

## Test data

Use fictional aliases and synthetic scenarios only. Never submit:

- real credentials or recovery material;
- account numbers, balances, transaction instructions, or tax identifiers;
- legal names, private addresses, itineraries, or household routines;
- live incident evidence, private messages, or confidential vendor information.

## Manual checks before a pull request

1. Load the demonstration profile.
2. Answer assessment items in every state, including `Not applicable`.
3. Confirm scoring, coverage, pillar bars, and roadmap stages update.
4. Add and remove a person, crown jewel, and trusted party using synthetic labels.
5. Complete and reset an incident playbook.
6. Activate travel mode and update each checklist group.
7. Export the share-safe action plan and verify no register labels appear.
8. Export and re-import an encrypted backup with a test password.
9. Print the roadmap and family verification card.
10. Clear all local data and verify the initial state returns.
11. Test keyboard navigation and a narrow mobile viewport.
12. Confirm the browser console shows no unexpected network requests or script errors.
